## TECHNICAL PRINCIPLES
- Nullable vs absent: `{"field": null}` ≠ `{}` (field absent). JSON Schema must distinguish.
- To make a field explicitly nullable: `"type": ["string", "null"]` or `"oneOf": [{"type": "string"}, {"type": "null"}]`
- Fields that ARE nullable must be in the `required` array — model should output them as `null` (not omit them)
- Fields not in `required` can be omitted — but this causes unpredictable model behavior
- Hallucination cause: model fills in required fields with invented data when real data is absent
- Fix: add field to `required` array AND make it nullable — model outputs `null` instead of fabricating
- `additionalProperties: false`: prevents model from adding fields not in schema
- `default` values in schema: not enforced by Claude — model may or may not use them
- For optional contextual fields: make them `["type", "null"]` and required — forces explicit signal
- Production impact: downstream systems cannot distinguish "field missing" from "field not applicable"
- Schema validation: always validate model output against schema before using it
- Common nullable fields: secondary_address, co_applicant_name, discount_code, referral_source
