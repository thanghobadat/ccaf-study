## TECHNICAL PRINCIPLES
- PreToolUse hook: intercepts BEFORE tool executes — use for: authorization, compliance, rate-limiting, input sanitization, prerequisite checks
- PostToolUse hook: runs AFTER tool executes — use for: logging, normalization, audit trails, metrics, caching
- CRITICAL distinction: PostToolUse CANNOT prevent an action already taken — only PreToolUse can block
- Hooks are deterministic: they run in EVERY case, unlike prompt instructions (probabilistic)
- Hook return values: PreToolUse can return modified input, block with error, or allow through
- Hook chaining: multiple PreToolUse hooks run in registration order — first block wins
- Hook failure modes: if hook throws unhandled exception, tool call may be skipped or fail depending on harness
- Use PreToolUse for: GDPR data access control, PCI-DSS card data masking, HIPAA PHI access logging (but also blocking)
- Use PostToolUse for: normalizing tool output format, enriching results with metadata, updating audit log
- Hook vs prerequisite gate: hooks are lifecycle callbacks; gates are inline code in tool definition
- SDK hooks are configured at the harness/framework level, not in the system prompt
- Hooks can inspect AND modify the tool call parameters before execution
