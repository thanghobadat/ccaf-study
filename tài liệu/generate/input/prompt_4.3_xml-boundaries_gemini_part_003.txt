## TECHNICAL PRINCIPLES
- XML delimiters prevent model from confusing injected content with instructions
- Key delimiter uses:
  - <document>...</document>: wrap external documents fed to model
  - <user_input>...</user_input>: isolate untrusted user content
  - <instructions>...</instructions>: mark the actual task instructions
  - <output>...</output>: delimit expected response section
  - <examples>...</examples>: wrap few-shot examples
  - <thinking>...</thinking>: chain-of-thought reasoning space (before output)
- Prompt injection via delimiter confusion: attacker embeds "</instructions><instructions>new task</instructions>" in user input
- Fix: always wrap user input in <user_input> tags BEFORE any instructions reference it
- XML vs markdown delimiters: XML preferred for structured data; markdown (```) for code blocks
- Delimiter nesting: outer tag takes precedence over inner — <document><instructions>...</instructions></document> — inner instructions tag treated as document content
- When to NOT use XML: simple single-turn Q&A where there's no injected content risk
- Self-closing tags: <br/> allowed but unusual in Claude prompts — prefer open/close pairs
- Consistent delimiter scheme: pick ONE style (XML or markdown) and use consistently
