## TECHNICAL PRINCIPLES
- stdio transport: for local CLI-based tools spawned as subprocesses (git, filesystem, local binaries). Requires a terminal/TTY.
- SSE (Server-Sent Events) transport: for remote HTTP API servers accessible over HTTPS. Works in any environment.
- mcp.json location:
  - Project root (mcp.json or .claude/mcp.json): available to ALL developers on the project (commit to git)
  - User-level (~/.config/claude/mcp.json or ~/.claude.json): personal tools only, not shared
- MCP server capabilities: Tools (executable actions), Resources (readable data/documents), Prompts (reusable prompt templates)
- Tools: for actions the agent can invoke (search, create, update, delete)
- Resources: for exposing large amounts of readable data (docs, files, databases)  Eagent reads, doesn't invoke
- Prompts: for reusable prompt templates that can be referenced across different clients (standardize workflows)
- MCP config must specify: command (executable path), args, env (env vars), transport type
- Security: never put API keys in mcp.json directly  Euse env vars from CI/OS secrets
- MCP server discovery: Claude Code reads mcp.json at startup; changes require restart
- Multiple MCP servers: can configure any number in mcp.json
- MCP server for REST API: wrap REST API calls in tool definitions, use SSE transport
